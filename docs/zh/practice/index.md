## 13. 让 AI 帮你读 GitHub：医护人员专用提示词

### 13.1 解释项目

```text
我是医疗人员，不是专业程序员。请帮我用通俗语言解释这个 GitHub 项目。
请按下面结构回答：
1. 这个项目解决什么医疗/科研问题？
2. 它适合医生、护士、科研人员还是工程师？
3. 输入数据是什么？输出结果是什么？
4. README 里最重要的 5 个信息是什么？
5. 它是临床可用、科研可用，还是教学 demo？
6. 有哪些隐私、安全、合规风险？
7. 我如果想试用，第一步该做什么？
```

### 13.2 判断项目是否靠谱

```text
请从医疗人员角度评估这个 GitHub 项目是否靠谱。
请检查：README、Star、最近更新时间、Issues、Release、License、数据来源、隐私说明、临床使用边界。
最后给出：推荐深入 / 可以学习 / 谨慎观察 / 不建议使用，并说明原因。
```

### 13.3 复现论文代码

```text
我想复现一篇医学 AI 论文的 GitHub 代码。请帮我检查这个仓库：
1. 是否提供完整代码？
2. 是否提供数据或数据获取方法？
3. 是否提供模型权重？
4. 环境安装是否清楚？
5. 是否有人在 Issues 里反馈无法复现？
6. 复现难度对非程序员来说是低、中还是高？
7. 我下一步应该做什么？
```

### 13.4 写医疗项目 README

```text
请帮我写一个医疗 AI 教学 demo 的 GitHub README。
要求包含：项目简介、适用人群、功能、安装方法、使用步骤、示例输入输出、隐私保护、安全边界、免责声明、License、联系方式。
请明确写：本项目仅用于教学和科研演示，不用于临床诊断或治疗决策。
```

### 13.5 写 Issue

```text
请帮我把下面的问题整理成一个礼貌、清楚、适合发到 GitHub 的 Issue。
我是医疗用户，请突出医学解释、数据字段、隐私风险或使用边界方面的问题。
结构包括：问题描述、复现步骤、为什么重要、建议修改、我的环境、截图/报错。
```

## 14. 课堂练习：30 分钟完成一次医疗 GitHub 入门闭环

### 练习目标

让医护人员完成一次完整流程：找项目 → 看 README → 判断风险 → 收藏 → 让 AI 解释。

### 步骤

1. 打开 GitHub；
2. 搜索 `medical ai` 或 `pubmed literature review`；
3. 选一个 README 看起来清楚的项目；
4. 记录项目名称和链接；
5. 看 Star 和最近更新时间；
6. 看有没有 Releases；
7. 看 README 是否写了数据来源和使用边界；
8. 看 Issues 里有没有安装失败或医学风险反馈；
9. 点 Star；
10. 把 README 复制给 AI，用本教材的提示词解释。

### 练习记录模板

```markdown
## 我今天看的医疗 GitHub 项目

- 项目名称：
- 项目链接：
- 它解决什么问题：
- 面向人群：医生 / 护士 / 科研人员 / 工程师 / 其他
- Star 数：
- 最近更新时间：
- README 是否清楚：清楚 / 一般 / 不清楚
- 有没有 Release：有 / 没有
- 是否说明数据来源：有 / 没有
- 是否说明隐私和安全边界：有 / 没有
- 是否可能用于临床：不能 / 仅研究 / 不确定 / 明确临床产品
- 我是否点了 Star：是 / 否
- 我最看不懂的地方：
- AI 帮我解释后的理解：
- 是否值得继续研究：值得 / 暂时不值得
```
