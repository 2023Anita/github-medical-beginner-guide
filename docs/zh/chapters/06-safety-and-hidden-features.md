## 10. 医护人员必须注意的 GitHub 安全边界

### 10.1 不要上传真实患者数据

不要放：

- 姓名；
- 身份证；
- 电话；
- 住院号；
- 门诊号；
- 影像原始文件；
- 病理号；
- 检查号；
- 可识别面部照片；
- 未脱敏病历；
- 小样本罕见病例细节。

即使你觉得“没人会看到”，公开仓库就是公开互联网。

### 10.2 不要上传密钥和账号

不要放：

- API key；
- token；
- 数据库密码；
- 医院系统账号；
- 云服务密钥；
- `.env` 文件；
- Kaggle / OpenAI / GitHub token。

如果不确定，先不要上传。

### 10.3 医疗 AI 项目必须写使用边界

如果你发布医疗相关项目，README 应该写清楚：

- 是否只供教学；
- 是否只供科研；
- 是否能用于临床；
- 是否经过验证；
- 输入数据要求；
- 输出结果不能替代医生；
- 需要人工审核。

### 10.4 开源不等于可以随便商用

看 License。

常见 License 包括：

- MIT；
- Apache-2.0；
- GPL；
- BSD；
- AGPL；
- 非商业许可证。

医疗软件、科研代码、模型权重、数据集可能有额外限制。

不要因为代码公开，就默认可以直接放进商业产品或临床系统。

## 11. GitHub 的隐藏功能：医护人员怎么用

### 11.1 GitHub Pages：发布个人科研主页或项目页

适合：

- 个人学术主页；
- 科研项目介绍；
- 医疗 AI demo 展示页；
- 课程资料页；
- 个人作品集。

比如你可以做一个页面展示：

- 我的研究方向；
- 论文列表；
- 开源项目；
- 医疗 AI 工具；
- 教学材料。

### 11.2 GitHub Actions：自动跑科研流程

可以用于：

- 定时更新文献列表；
- 自动生成数据报告；
- 自动检查代码是否能运行；
- 自动部署文档网站；
- 自动构建教学页面。

新手先知道它存在即可，不用一开始就写。

### 11.3 GitHub Gist：保存小脚本

适合保存：

- PubMed 检索式；
- R 语言画图代码；
- Python 数据清洗片段；
- Markdown 表格模板；
- 常用命令。

### 11.4 Discussions：项目讨论区

如果一个医疗 AI 项目开启 Discussions，你可以在那里问：

- 数据输入格式；
- 适用疾病；
- 论文复现问题；
- 临床解释；
- 使用边界。
