## 3. Git 和 GitHub 有什么区别？用病历系统来类比

很多人把 Git 和 GitHub 混在一起。

其实它们不是一个东西。

| 概念 | 通俗解释 | 医疗类比 |
|---|---|---|
| Git | 版本管理工具 | 病历修改痕迹 / 医嘱历史记录 |
| GitHub | 在线托管和协作平台 | 医院信息系统里的项目档案室 + 协作平台 |

### 3.1 Git：记录每一次修改

Git 的作用是记录版本。

就像电子病历里，医生修改病程记录、护士修改护理记录、药师审核医嘱，系统会留下时间、人员、修改痕迹。

软件项目也需要这样。

比如你让 AI 改一个科研统计脚本：

- 第一版：能读入 Excel；
- 第二版：加了缺失值处理；
- 第三版：加了 Cox 回归；
- 第四版：AI 改坏了，结果跑不出来。

如果没有 Git，你可能不知道哪里坏了。  
如果有 Git，你可以回到第二版或第三版。

### 3.2 GitHub：把项目放到网上管理

GitHub 是平台。

它让你可以：

- 查看项目文件；
- 阅读 README；
- 下载源码或安装包；
- 收藏项目；
- 提 Issue；
- 和别人协作；
- 展示自己的研究工具；
- 发布个人主页或项目页面。

### 3.3 医护人员先学哪个？

第一阶段：先学 GitHub 网页。

你先会：

- 看 README；
- 看 Releases；
- 看 Issues；
- 点 Star；
- 下载 ZIP；
- 创建仓库；
- 写 README。

第二阶段：再学 Git 命令。

你再学：

- `clone`：把项目复制到本地；
- `commit`：保存一次修改；
- `push`：上传到 GitHub；
- `branch`：开一个实验分支；
- `pull request`：请求别人合并你的修改。

> **对医护人员来说，先拥有 GitHub 阅读能力，再拥有 Git 操作能力。顺序不要反。**

## 4. 医疗 AI 时代，为什么更需要 GitHub？

### 4.1 医疗 AI 项目越来越多，但质量差异很大

现在很多项目会叫自己：

- medical AI；
- clinical AI；
- healthcare agent；
- radiology AI；
- EHR NLP；
- diagnosis assistant；
- medical chatbot。

但名字里有 medical，不代表它能用于临床。

你需要判断：

- 它是研究 demo，还是临床产品？
- 有没有说明数据来源？
- 有没有评价指标？
- 有没有安全边界？
- 是否有医学人员参与？
- 是否声明不能替代医生？
- 是否涉及真实患者数据？
- 是否有许可证？

GitHub 阅读能力，可以帮你初步判断项目边界。

### 4.2 论文复现经常需要 GitHub

很多医学 AI 论文会在文末写：

> Code is available at GitHub: ...

如果你做科研，需要知道：

- 代码是否真的公开；
- 是否有安装说明；
- 是否有数据说明；
- 是否能复现论文结果；
- 是否只公开了部分代码；
- 是否依赖无法获得的数据集；
- 是否多年未更新。

不会看 GitHub，就很难判断一篇 AI 论文是否可复现。

### 4.3 医院内部小工具也需要版本管理

很多医护人员会做一些小工具：

- Excel 自动整理；
- 科研数据清洗；
- 随访表单；
- 科室排班；
- 质控报表；
- 文献筛选；
- 病例教学素材整理；
- 临床路径可视化；
- 术前评估表；
- 患教材料生成。

这些工具一开始可能只是个人用。  
但一旦多人使用，就需要：

- 版本记录；
- 说明文档；
- 变更记录；
- 使用边界；
- 问题反馈；
- 权限管理。

GitHub 正好提供这些基础能力。

> 注意：真实患者数据、内部敏感资料、API key、账号密码，不要放到公开 GitHub 仓库。
