## 12. 最容易踩的坑：医疗人员版

### 坑 1：把 GitHub 项目当成临床可用产品

GitHub 上很多项目只是 demo。

即使它叫 medical AI，也不代表能用于临床。

要看：

- 是否经过临床验证；
- 是否有监管批准；
- 是否有真实世界评估；
- 是否有风险声明；
- 是否有人负责维护。

### 坑 2：看到模型结果就当医学结论

模型输出不是诊断。

尤其在：

- 影像识别；
- 病理分析；
- 风险预测；
- 诊断建议；
- 用药建议；
- 分诊建议。

必须有专业人员审核。

### 坑 3：下载源码后以为能直接双击运行

源码不是安装包。

源码通常需要：

- Python / R / Node 环境；
- 依赖安装；
- 配置文件；
- 模型权重；
- 示例数据；
- 命令行运行。

所以先读 README，优先看 Release。

### 坑 4：把真实数据传给网页 AI 或公开仓库

不要把真实病历、检查报告、影像、身份信息复制到第三方网页 AI、公开 issue、公开仓库。

如果需要测试，用虚构数据或严格脱敏数据。

### 坑 5：只看 Star，不看医学适用性

Star 多说明关注多，不说明医学安全。

医学场景还要看：

- 数据来源；
- 验证队列；
- 人群差异；
- 指标定义；
- 偏倚风险；
- 是否有医生参与；
- 是否声明用途限制。

## 13. 让 AI 帮你读 GitHub：医护人员专用提示词

### 13.1 解释项目

```text
我是医疗人员，不是专业程序员。请帮我用通俗语言解释这个 GitHub 项目。
请按下面结构回答：
1. 这个项目解决什么医疗/科研问题？
2. 它适合医生、护士、科研人员还是工程师？
3. 输入数据是什么？输出结果是什么？
4. README 里最重要的 5 个信息是什么？
5. 它是临床可用、科研可用，还是教学 demo？
6. 有哪些隐私、安全、合规风险？
7. 我如果想试用，第一步该做什么？
```

### 13.2 判断项目是否靠谱

```text
请从医疗人员角度评估这个 GitHub 项目是否靠谱。
请检查：README、Star、最近更新时间、Issues、Release、License、数据来源、隐私说明、临床使用边界。
最后给出：推荐深入 / 可以学习 / 谨慎观察 / 不建议使用，并说明原因。
```

### 13.3 复现论文代码

```text
我想复现一篇医学 AI 论文的 GitHub 代码。请帮我检查这个仓库：
1. 是否提供完整代码？
2. 是否提供数据或数据获取方法？
3. 是否提供模型权重？
4. 环境安装是否清楚？
5. 是否有人在 Issues 里反馈无法复现？
6. 复现难度对非程序员来说是低、中还是高？
7. 我下一步应该做什么？
```

### 13.4 写医疗项目 README

```text
请帮我写一个医疗 AI 教学 demo 的 GitHub README。
要求包含：项目简介、适用人群、功能、安装方法、使用步骤、示例输入输出、隐私保护、安全边界、免责声明、License、联系方式。
请明确写：本项目仅用于教学和科研演示，不用于临床诊断或治疗决策。
```

### 13.5 写 Issue

```text
请帮我把下面的问题整理成一个礼貌、清楚、适合发到 GitHub 的 Issue。
我是医疗用户，请突出医学解释、数据字段、隐私风险或使用边界方面的问题。
结构包括：问题描述、复现步骤、为什么重要、建议修改、我的环境、截图/报错。
```
